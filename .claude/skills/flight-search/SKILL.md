# 航空券の最安ルート探し（マイク用手順）

ユーザーから日程・区間が出たら、聞き返さずに以下を一気に実行して**提案まで**出す。
移動の話が出たら、頼まれていなくても「最安ルートを出しましょうか」ではなく**最安ルートを出す**。

## 絶対ルール

- **米国・カナダ経由は常に除外**（ESTA / eTA が取れない）。乗継だけでも不可。
  結果に次の空港が含まれていたら捨てる：
  米国 `JFK EWR LGA IAD DCA ORD ATL DFW IAH MIA LAX SFO SEA DEN BOS PHX LAS MCO CLT DTW MSP PHL HNL GUM SPN` など全米国空港、
  カナダ `YVR YYZ YUL YYC` など全カナダ空港
- 出発地は **基本「大阪（KIX）」**。東京（HND・NRT）は比較として調べ、「新幹線 片道約1.5万円＋必要なら前泊」を足した実質額で比べる
- 別切り（セパレート）の乗継は最低5〜6時間、長距離便の後は1泊。1泊するならその都市の観光案として出す

## 使う道具（上から順に、使えるものを使う）

1. **Kiwi.com コネクタ**（`search-flight`）— 別切りの組み合わせまで自動で探す。最安探しの本命
2. **Turkish Airlines コネクタ** — トルコ経由の公式運賃・セール確認
3. **Expedia コネクタ** — 通し券の比較
4. どれも無い場合：WebSearch で相場を調べ、`tools/flight-planner.html` のカレンダーとルート案で候補日を絞り、
   ユーザーに Trip.com で見てもらう日付・区間を**具体的に**指示する

## 道具の使い分け（実績から）

- Turkish コネクタの往復は、往路一覧の金額が**往路分だけ**。必ず `search_inbound_flights` まで進め、
  deeplink の `prc=`（往復合計）で総額を確認する（往路表示だけで往復額と誤認した前例あり）
- Kiwi の往復は片道の足し算で割高になりがち
- 片道・別切りの最安探しは Kiwi（`exclude_stopover_countries: "US,CA"`、`currency: "JPY"`、預け荷物1個を指定）
- Turkish コネクタは KIX→ASU のように提携社区間（GOL・コパ）込みで通し運賃を出せる。
  結果が大きいのでファイルを jq で読む（`originDestinationOptions[].cheapestPriceAmount`、
  `bookingPriceInfos[]` に荷物・変更・払戻条件）
- Expedia コネクタはエラーになることがある（予備扱い）

## 見落とし防止（2026-09-30 の反省）

- 往復も比較として東京発（HND・NRT）を検索する（ただし基本は大阪発）
  （Trip.com で HND 発・中国国際航空＋別切りの往復 ¥306,300 を見落とした）
- 中国系（中国国際航空・中国東方・中国南方）経由も必ず候補に入れる。安いことが多い
- 比較は運賃の表示額でなく**実質総額**で：表示運賃＋東京までの移動（新幹線 約1.5万円）
  ＋前泊ホテル（朝発なら）＋乗継地ホテル（1泊乗継なら）
- 「手荷物の受け取り・再チェックイン」表示＝別切り。遅延時の補償がないリスクとして明記
- ユーザーは Trip.com を見ている。Trip.com に出る組み合わせ（航空会社をまたぐ別切り往復）は
  Kiwi の片道検索を往路・復路で個別に回し、足し算で近似する

## 実績メモ

- 日本⇔南米は「中国国際航空の往復（北京経由、日本⇔サンパウロ）＋最後の短距離を別切り」が最安になりやすい
  （2026-09 時点で往復 ¥30万台。Kiwi の片道足し算・欧州発の往復は ¥40万超）
- Kiwi で見つからない往復運賃は Trip.com にある。ユーザーに Trip.com で見てほしい条件を具体的に指示する

## 手順

1. **候補日を絞る**：`docs/flight-optimization.md` の繁忙期（旧正月・カーニバル・セマナサンタ・日本の連休）を避け、
   火・水出発を優先。希望日の前後3日を検索対象にする
2. **検索**：KIX発・東京発 × 候補日 × 片道/往復。米国・カナダ経由を除外
3. **組み合わせ**：通し券だけでなく「長距離は通し＋最後の短距離は別切り」「中継都市で1泊観光」も作る
4. **マイル比較**：同じ区間を ANA／ユナイテッド／Aeroplan で取った場合の見積もりを添える
   （マリオット 60,000pt → 通常25,000マイル、ユナイテッドのみ30,000マイル。
   1マイルの価値＝（現金−特典の税燃油）÷必要マイル。通常2.0円・ユナイテッド1.6円以上なら特典）
5. **提案**：結論から。安い順に3案まで、各案に「日付・便・経由地・所要・金額・途中観光・リスク」を書く。
   1案に絞って「これで取りましょう」と推す
6. **記録**：決まった案は `docs/flight-optimization.md` に追記し、コミットする

## 出力の型

| 順位 | 日付 | 経路（便） | 所要 | 総額 | 途中観光 | 注意 |
|---|---|---|---|---|---|---|

最後に「予約する順番」（例：長距離を先 → 別切り区間 → マリオット移行）を1〜3行で。
